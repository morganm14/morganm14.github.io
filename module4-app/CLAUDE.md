# Module 4 App

Shared context. Read this file first, every session, before touching anything else.

## The map

| File | What it holds | Who writes it |
|---|---|---|
| `problem.md` | The problem: who has it, what it costs them, why now | Me, with the agent |
| `evidence.md` | Proof the problem is real: sources, numbers, quotes. Every claim has a source. | Me, with the agent |
| `solution.md` | **The build spec.** What the app does, for whom, screens/features, what's out of scope | Me, with the agent |
| `web-page.md` | Landing-page copy for the app | Agent drafts, I edit |
| `ad-script.md` | Short ad script for the app | Agent drafts, I edit |

## The order

`problem.md` → `evidence.md` → `solution.md` → **app** → `web-page.md` + `ad-script.md`

Each file builds on the one before it. Don't start a file until the one before it exists.

## The rules

1. **`solution.md` is the only source for building the app.** If a feature isn't in
   `solution.md`, don't build it — ask me to add it first.
2. **No invented evidence.** Only cite what's in `evidence.md`. If a claim has no source, say so.
3. **One file at a time.** Only edit the file I ask about. Don't "fix" other files on the side.
4. **Marketing matches the build.** `web-page.md` and `ad-script.md` can only promise
   what `solution.md` actually delivers.
5. Keep it short. Plain language, bullet points over paragraphs.
